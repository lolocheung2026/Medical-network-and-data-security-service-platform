# ADR-0003：v0.3 脱密引擎白名单制加固

日期：2026-09-26
状态：已接受

## 背景

v1 脱密引擎阻断策略为"同一文件检出 ≥3 处证件号/手机号 → 拒绝"（阈值=3 经验值）。
方案第七节风险 #1（变形写法漏检）、#4（1 条身份证也应拒绝）要求 v0.3 加固。

## 决策

1. **白名单制阻断**：数据字典仅允许 schema 级描述文本，检出任何 PII 值（≥1 处）
   即整体拒绝入库，废弃阈值=3 与"清除后放行"路径。拓扑路径同样适用（IP 除外，
   IP 是拓扑合法元素，仍走假名化）。
2. **变形写法覆盖**：新增身份证加空格/连字符、手机号带分隔符两组变形正则；
   变形正则要求至少一个分隔符，避免与标准正则重复计数。
3. **繁体机构名**：机构名线索正则覆盖「醫院」「衛生院」等繁体写法。
4. **误报权衡**：11 位数字串（如主键 ID）可能被手机号规则误拦，属可接受代价
   （宁严勿漏），人工校正回流通道由分类模块规则回流机制承接（v0.3 后续项）。

## 影响

- `app/sandbox/deidentify.py` 升级 v2（删除 BLOCK_THRESHOLD，新增变形正则）
- 上传行为变化：单处 PII 从"脱密放行"变为"拒绝入库"

## 冒烟证据（2026-09-26 实测）

- 单元自测 10/10：合法字典放行、连写/带空格/带连字符证件号均拒、
  手机号连写与带分隔均拒、邮箱拒、繁体机构提示、拓扑 IP 假名化、拓扑 PII 拒
- 端到端：单处证件号上传 → status=rejected；合法字典 → deidentified
- 回归：3 处 PII 阻断、推演落库、登录均正常（修复 run.py debug 双进程后基线绿）

## 未决项

- 白名单制误报率实测：需要真实医院字段命名样本验证（假设性预判：11 位
  数字主键、8 位日期字段可能误拦，需人工校正通道回流）
- 脱密算法重识别攻击测试（v1.0 前必测项）仍需第三方执行
