## 一、产品定位

**一句话**：科研院所面向区县卫健委与中小医疗机构提供的公益性网络与数据安全 SaaS 服务平台——客户登录网站，进入对应功能模块，即可获得数据分类分级、攻防推演、合规判断三类服务。

| 维度 | 定案 |
|------|------|
| 产品形态 | 整体解决方案（平台 + 运营服务），Web/SaaS 入口 |
| 服务模式 | 科研院所公益免费 + 免责声明；先积累影响力，后考虑收费 |
| 目标客户 | 区县卫健委、中小型医疗机构（三甲医院作为灯塔共建，不作首单目标） |
| 核心差异化 | 医疗专用沙盒（内置自动脱密）+ 纯仿真攻防推演（零接触客户真实网络） |

## 二、功能体系（三大功能 + 一个沙盒）

### 2.1 数据自动分类分级（首发）
- 输入：客户上传的数据字典（schema 级：表名/字段名/注释）
- 引擎：关键词规则 → GB/T 39725《健康医疗数据安全指南》五级定级（L1 可公开 → L5 极敏感：基因/生物识别/精卵胚胎/传染病）
- 输出：逐字段定级 + 命中规则溯源 + 敏感级别分布统计
- 状态：v1 已实现并实测通过

### 2.2 攻防推演 + 整改报告（核心差异化，二期迁移）
- 纯数字仿真：基于脱密拓扑图建数字孪生，跑攻击路径/脆弱性传导/蒙特卡洛推演，输出整改报告
- 边界锁死：不做真实扫描、不做渗透，永不触碰客户生产网络
- 复用资产：沙盘项目 engine/（攻击图、对抗画像 LockBit 3.0/APT41、蒙特卡洛 95% CI、六步工作流）、18 个推演场景、CVE 库 47 条 + 合规条文库
- 先例：BAS 类厂商（如 Invicti）均走仿真验证路线；医疗领域纯仿真推演尚无头部玩家（假设性预判，需正式竞品调研确认）

### 2.3 网络与数据行为合规判断（二期殿后）
- 三件套锚点：等保 2.0（三级基线）+《医疗卫生机构网络安全管理办法》（行业专项）+ GB/T 39725（分类分级）
- 明确不碰：商用密码应用评估（密评）——报告仅引导咨询密评机构
- 依赖：一期分类分级产出的数据资产清单

### 2.4 医疗专用沙盒 + 自动脱密引擎（守门员，已实现 v1）
- 唯一数据入口，所有上传必经脱密
- 阻断策略：同一文件检出 ≥3 处证件号/手机号 → 判定原始医疗数据，整体拒绝入库（实测通过）
- 脱密策略：IP 地址假名化（保留连通关系）、机构名租户盐哈希假名化、零星 PII → `<REDACTED>`
- 输出：脱密后文本 + 脱密报告（动作明细 + 重识别风险标记）

## 三、数据红线（最高约束）

1. 原始医疗数据不出院：平台只接收数据字典（schema 级）与脱密后拓扑图
2. 不碰密评
3. 不做真实扫描/渗透
4. 免费不等于免责模糊：登录强制签署免责声明（参考性建议，不构成测评结论，不替代等保测评）

## 四、技术架构

```
用户浏览器（卫健委/中小医院）
  → Web 入口层：Flask，登录认证 + 租户网关（tenant_id 全链路隔离）+ 免责声明
  → 自动脱密沙盒（唯一数据入口，红线拦截）
  → 功能模块：分类分级引擎 / 攻防推演引擎 / 合规判断 / 报告中心
  → 数据层：SQLAlchemy（SQLite 起步，预留 PostgreSQL），表级 tenant_id 隔离
```

| 决策 | 定案 | 理由 |
|------|------|------|
| 后端 | Flask 扩展，不换框架 | 沙盘种子代码复用最大化 |
| 数据库 | SQLite + SQLAlchemy，预留 PostgreSQL | 本机开发零依赖，上云无缝迁移 |
| 多租户 | 表级 tenant_id 隔离 | 最简方案，不上 schema 隔离 |
| 前端 | 沿用沙盘 Canvas/SVG 拓扑渲染体系 | 推演可视化是核心卖点 |
| 部署 | 本机 Mac 开发；上云方案按"未来上云"预留（ORM 无关、密钥走环境变量） | 避免返工 |

## 七、风险登记（假设性预判，未经证实）

| # | 风险 | 等级 | 对策 |
|---|------|------|------|
| 1 | 脱密引擎正则驱动，变形写法（加空格证件号、繁体机构名）可能漏检 | 高 | v0.3 改白名单制；第三方重识别攻击测试验证 |
| 2 | 分类规则硬编码，真实医院字段命名多样，首月命中率可能不足 60% | 中 | ✅ 人工校正回流通道已建（ADR-0009）；观察期决策（2026-09-26 乐叔定）：观察校正数据 1-2 周，按高频校正词审慎扩词（统计接口 /classify/corrections/stats） |
| 3 | SQLite 单文件在 50+ 租户并发上传时可能写锁竞争 | 中 | 上云前切 PostgreSQL（已预留） |
| 4 | 阻断阈值=3 为经验值，真实场景 1 条身份证也应拒绝 | 高 | v0.3 改"任何 PII 值出现即拒"（schema 白名单语境） |
| 5 | 集中存放多家医院数据字典+拓扑，平台自身成攻击目标 | 高 | 平台等保三级规划 + 专项经费 + 第三方测试 |
| 6 | 两人开发持续性风险（AI 会话制、乐叔精力） | 中 | GitHub + ADR + 本方案文档，任何接手方可续 |

## 八、验收标准

1. 功能：三大功能冒烟测试通过（分类定级可溯源、推演报告可生成、合规判断规则命中）
2. 安全：第三方渗透测试 + 代码审计通过；脱密算法经重识别攻击测试
3. 合规：免责声明签署率 100%；原始数据阻断机制有效（攻击样本测试集）
4. 文档：ADR 持续更新；本方案随版本演进
