# ADR-0006：v1.0 合规判断模块骨架

日期：2026-09-26
状态：已接受

## 背景

路线图 v1.0 = 合规判断模块（三件套规则库）+ 多租户打磨 + 第三方安全测试。
本 ADR 记录合规模块骨架的设计决策（规则内容由乐叔按官方文本审定后填充）。

## 决策

1. **检查项结构**：ComplianceItem（条文库）= anchor（锚点）+ article（条款号）+
   title + provision（条文原文/要点）+ checkpoint（可判定检查点）+
   evidence_hint（证据要求提示）。判定对象是"检查点"而非"条文"，保证可执行性。
2. **条文库平台级共享**：ComplianceItem.tenant_id=0 表示平台内置，所有租户
   复用同一套检查项（条文是公共法律/标准，无租户差异）；评估记录
   （ComplianceAssessment）严格租户级，满足表级隔离。
3. **判定四值**：符合 / 不符合 / 不适用 / 待评估（默认）。证据为客户自述文本
   （≤2000 字），不做真实性核验——报告明确"参考性整理，不构成等保测评结论"。
4. **不碰密评**：报告 disclaimer 固定引导"商用密码应用评估请咨询密评机构"。
5. **样例条文标注**：SEED_ITEMS 5 条（等保 2.0 三级 2 条 + 管理办法 2 条 +
   GB/T 39725 1 条）仅用于结构验证，模板与页面均标注"样例占位，待审定"。
   条文原文最终以官方发布文本为准，由乐叔审定后替换（组织分工：乐叔出领域规则）。
6. **汇总口径**：符合率 = 符合 / (总项 - 待评估)，排除不适用项由页面分列展示。

## 影响

- `app/models.py`：+ComplianceItem / +ComplianceAssessment（均含 tenant_id）
- `app/compliance/routes.py`：占位 /status 重写为完整骨架（列表/提交/汇总/状态）
- `app/templates/compliance.html`（新增）、base.html 导航 +"合规判断"
- `app/__init__.py`：create_app 时 seed_items()（幂等）

## 冒烟证据（2026-09-26 实测）

- 合规页 200，三锚点分组渲染 5 项；汇总接口 total=5
- 评估提交 302 → 符合率 100% → 落库（tenant_id=1 隔离正确）

## 未决项

- 正式规则库：等保 2.0 三级全部控制点（8.1.x）逐条翻译、管理办法逐条、
  GB/T 39725 分类分级检查点——待乐叔审定（工作量估计为其半天+）
- 与分类分级模块联动：数据资产清单自动映射合规检查点（v1.0 后续项）
- 证据附件上传（截图等）当前仅文本，是否支持附件待定
