# ADR-0005：脱密引擎 v3 校验和验证（开源借鉴）

日期：2026-09-26
状态：已接受

## 背景

乐叔要求检索 GitHub 相关开源项目并用于平台优化。检索结果评估：

| 候选 | star | 许可证 | 评估结论 |
|------|------|--------|---------|
| Microsoft Presidio（data-privacy-stack） | 11k | MIT | 工业级 PII 框架（NER+正则+规则+校验和+上下文）。直接复用问题：NER 优势在自由文本，本平台输入为结构化 schema 字典文本；中文支持需自建 recognizer + 模型（数百 MB）。不适配，借鉴其 checksum 识别器设计。 |
| pii-guard | 148 | MIT | 繁體中文 PII 工具（Presidio+CKIP NER+台湾 regex）。场景为 LLM 前脱敏代理，模型 500MB。不适配，借鉴其证件类型清单。 |
| funNLP | 83k | 无明确 | 中文 PII 资源集，可作模式参考。 |
| openmed | 5.4k | Apache-2.0 | 本地医疗 AI，HIPAA 去标识化，依赖重（模型），适配成本高，不采用。 |
| 等保/GB/T 39725 规则集 | — | — | GitHub 无成规模开源规则集，规则仍以乐叔领域知识为主。 |

结论：直接复用均不匹配（输入形态=结构化字典；零依赖是平台既定约束），
采纳 Presidio 核心设计——**校验和验证**——纯标准库实现（约 40 行）。

## 决策

1. **身份证校验和验证（GB 11643-1999）**：命中正则后归一化（去分隔符）做
   加权 mod 11 校验。校验通过 = 必然合法证件 → 阻断；校验失败 = 必然非合法
   证件（业务编号，如 18 位主键）→ 降级为 risk_flag"建议人工复核"，放行。
   **零漏检**：真实身份证必过校验和。
2. **银行卡 Luhn 校验**：新增 16-19 位卡号识别（v2 未覆盖银行卡）。Luhn
   通过 → 阻断；失败 → risk_flag 放行。与身份证重叠的候选已剔除，避免重复报。
3. **证件模式扩充（借鉴 pii-guard 清单）**：中国大陆护照 E+8 位、港澳通行证
   C+8 位、澳门证件 M+8 位、香港身份证 [A-Z]+6 位+(校验位)。
4. **手机号维持硬阻断**：无可靠校验和，宁严勿漏（ADR-0003 定案不松动）。
5. **阻断策略不变**：白名单制"任何 PII 值出现即拒"保留；本 ADR 提升的是
   识别精度（区分真 PII 与业务编号），非放宽策略。

## 影响

- `app/sandbox/deidentify.py` 升级 v3（+校验函数、+3 组证件正则、_find_pii 返回
  risk_flags 分级处理），单文件约 200 行，仍守 300 行红线。

## 冒烟证据（2026-09-26 实测）

- 算法自检：GB 11643 公开示例 11010519491231002X 校验 True；Luhn 标准向量
  79927398713 校验 True
- 单元自测 21/21：真/伪身份证（连写、带分隔、带连字符）、真/伪银行卡、
  手机号、邮箱、病历号、护照、港澳台证件、合法字典、拓扑 IP 假名化、
  拓扑 PII 阻断全过
- 端到端：伪 18 位主键 → deidentified + risk_flag 提示；真身份证 → rejected

## 未决项

- 手写错误/涂改的真实身份证号（校验失败）会被降级放行——边缘场景，由
  risk_flag 提示人工复核兜底（假设性预判：此类场景占比极低）
- 手机号误报仍无法消解（无校验和可用），维持宁严勿漏
